JPEGView Changelog
******************

[Unreleased]
New features:
- Saving: the compression ratio of lossy JP2 files is configurable with the JP2LossyRate INI key (1..100, default 10, the historical 10:1); lossless JP2 ignores it
- Loading: the pixel cap (MaxImagePixelsMP) is off by default now; the hard byte cap (MAX_IMAGE_BYTES) and the 65535-pixel dimension limit still bound every allocation. Set 1..4096 megapixels to restore an explicit cap. WIC-only formats (*.wdp/*.jxr/*.dds) keep WICLoader.dll's own fixed 256 MP cap, which this setting cannot change
- JPEG saving: chroma subsampling is now configurable via the JPEGSaveSubsampling INI key (444/422/420, default 420, the historical behaviour); 444 keeps full chroma resolution for the best quality
- JPEG saving: ICC profile, XMP metadata, Photoshop/IPTC data, JFIF density and COM comment segments from the original file are now preserved on save, in their original order (previously only the EXIF segment was copied)
- HDR (.hdr) viewing: the GAMMA header is now honoured when converting to 8-bit, so files written for gamma 0.454545 are no longer displayed far too bright; files without a GAMMA header (or GAMMA=1.0) render byte-identically to before
Bugs fixed:
- PNM viewing: a portable anymap with a maxval below 255 (4-bit/6-bit samples, common from older and scientific tools) is scaled to full range instead of being displayed at maxval/255 of its brightness - a legal maxval=15 PGM used to render almost black instead of white
- TGA viewing: a 15-bit RLE file consumed one byte per pixel instead of two, so every pixel after the first was read from the wrong offset and the image decoded to noise; 15bpp now uses two bytes like the uncompressed path
- JPEG viewing: an Exif APP1 that is not the first APP1 (XMP written in front of it, as exiftool -o and some phones do) is found again, so orientation, camera data and timestamps are no longer dropped for those files
- JP2 viewing: a file whose reference grid has x1 <= x0 (or y1 <= y0) is rejected before the dimension subtraction can wrap
- HDR viewing: negative or NaN samples no longer reach an undefined float-to-int cast (they clamp to 0, like the EXR decoder)
- JPEG saving: when the EXIF thumbnail cannot be rebuilt, the old thumbnail is dropped instead of staying in the file and showing the previous picture
- Renaming: the new name is validated for illegal characters, reserved device names (CON, PRN, AUX, NUL, COM1-9, LPT1-9), a trailing dot or space and an empty title before anything is touched; an empty title no longer becomes ".jpg"
- Batch rename/copy: the whole batch is pre-checked (invalid names, duplicate targets, targets that already exist) and nothing is changed when a conflict is found; if a later operation fails and the user aborts, the operations already applied are rolled back
- Lossless JPEG transformations: the private 50 MB file limit was below the loader's own limit, so a file that could be opened could not be rotated or cropped; the loader's limit is used now
- Resource handling: the wallpaper registry key is closed after use, the shared ICC profiles are created once under a lock, and the help and print objects are released at shutdown
- Directory watching: a bare drive path ("C:") is normalised to its root, and a path that does not fit MAX_PATH is logged instead of being truncated silently
- PNG viewing: the gAMA/sRGB chunk now follows UseEmbeddedColorProfiles; with the switch off the file gamma is ignored (previously the image changed anyway, and a file carrying iCCP lost both the profile and the gamma)
- Clipboard: a CF_DIB block pasted from another application is validated against GlobalSize before GDI+ reads it (header, palette and pixel extent), so a negative width or an undersized block is rejected instead of being read out of bounds
- JP2 and PAM viewing: an embedded alpha channel is composited over white, like the SVG and EXR decoders, instead of being dropped (transparent pixels used to show their raw, often black, colour)
- Saving: the lossless choice is remembered per format; saving a lossless JP2 no longer makes the next WebP/JXL save dialog default to lossless
- OCR: selecting non-adjacent lines keeps the blank lines between them instead of collapsing them into one newline
- Localisation: four UI messages (image size limit, settings save failure, wallpaper failure, clipboard out of memory) added to the English, Simplified Chinese and Traditional Chinese string tables; the parameter-DB command that saves was described as "delete from parameter DB" in the generated key map
- Fixed the navigation-panel black bar that appeared while paging to the next image (the panel rectangle was painted black by FillRect during the wait-phase NULL paint). OnPaint now returns early while waiting for the new image (m_bWaitingForImage flag, RAII-guarded around RequestImage in GotoImage and OpenFile), preserving the previous frame.
- Saving settings now reports a failure instead of silently discarding it (SaveSettings reports success/failure and a message box shows the INI path on failure)
- A custom KeyMap.txt stored in AppData is now migrated to the EXE directory like the INI file, instead of being silently discarded in EXE mode
- Setting the desktop wallpaper now shows an error message when it fails instead of only writing a debug log line
- Post-build script: Config and LICENSE.txt copy failures now fail the build (exit-code check like the DLL copies) instead of being silently ignored
- Slide show lists: a list holding two files with the same name in different folders no longer jumps to the wrong image after a reload or a sort; the current file is found by its full path instead of its title only
- Image rotation in memory now marks the image as destructively processed, so a following lossless JPEG transformation cannot silently discard the unsaved edit
- Load failures caused by an unhandled exception are no longer memoized as permanently bad files; genuine decode failures are still remembered
- JPEG decoding via GDI+ now keeps the EXIF block, the file hash, the preserved APP/COM segments and the real chroma subsampling, so lossless transform and crop MCU checks no longer assume 4:2:0 for 4:4:4/4:2:2 files
- Animated WebP/APNG/JXL: the requested frame index is now passed to the decoder, so returning to a file or wrapping the animation restarts at frame 0 instead of showing the cached decoder's next frame under a frame-0 label
- APNG: a corrupt frame now clears libpng's error-state decoder immediately instead of leaving it in the cache for the next read
- ICC colour transforms now accept an explicit output row stride and reject plane sizes that would overflow the 32-bit lcms2 API (defensive; decode paths are already bounded by the image byte cap)
- PSD CMYK files without a usable ICC profile are now converted with the same naive CMYK-to-RGB formula as JPEG, instead of blending the K channel as alpha over black
- Histogram LUT calculation guards the midpoint denominators against zero on extremely tinted images
- PSD CMYK files with a malformed channel count no longer enter the 4-byte YMCK conversion and read past the allocated buffer
- Lossless JPEG transform menu: only the six lossless items are greyed out now, so Convert to JXL stays available after an in-memory rotation
- ICC colour transforms reject an explicitly supplied output row stride that is smaller than one output row, instead of overlapping rows
- Release workflow validates that the release notes headline and both download asset names match the tag before publishing
- JXL loading: the exception handler no longer leaks the file buffer or the EXIF chunk, and no longer risks freeing a buffer owned by the JXL reader cache (double-free)
- SVG viewing: rapid paging through SVG files no longer crashes (access violation in libthorvg-1.dll); the whole ThorVG session is now serialised across load threads instead of only init/term
- Finding a file that left the folder list (e.g. deleted externally) no longer silently shows the first image; the missing-file state is shown instead (or the empty state when the folder really has no images) (F-H02)
- JPEG saving: a preserved ICC profile whose colour space is not RGB (e.g. a CMYK profile on a CMYK source saved as RGB) is no longer kept on the output file
- Parameter DB: opening ParamDB.db now retries a transient sharing violation (up to ~2 s) instead of immediately showing the "Parameter DB error" dialog, so a fast relaunch no longer fails when the file is briefly locked by another process
- Pressing a sort key now re-enumerates the folder, so files deleted externally drop out of the list (and the missing-file state is shown if the current file is gone) instead of staying until the next reload
- Deleting the current file externally no longer shows the false "does not contain any image files" message when the folder still has images; the missing file is named and every page-turn input (arrow keys, other mapped keys, mouse wheel, navigation panel buttons) moves on to the neighbouring image instead of doing nothing
- RAW loading: some RAW files (e.g. Nikon D5000 NEF, Sony A100 ARW) were wrongly rejected by the TIFF gate because the next-IFD chain pointer after a SubIFD was followed without validation; manufacturers do not maintain that pointer, so the gate now only follows it when it lands on a structurally plausible IFD
- RAW loading: a Nikon D60 NEF was still wrongly rejected by the TIFF gate because the next-IFD pointer after a SubIFD can point inside the file at raw image data that parses as an IFD with insane dimensions; the gate now only follows the next-IFD chain at the top level (IFD0), matching dcraw, which never reads a SubIFD's next pointer
- RAW loading: a TIFF gate rejection is no longer memoized as a bad file for the session; a rejected file is re-attempted on the next visit (the gate runs before any decoder, so retrying it only re-runs the cheap header parse), instead of locking the file out until it changes or is released
- RAW loading: a TIFF gate rejection now writes one debug-log line per file ("JPEGView: TIFF gate rejected ...") with the reason code, the IFD offset and the offending values, so a false rejection can be diagnosed from the log instead of from a user report
- RAW loading: a broken SubIFD or a broken chained IFD no longer rejects the whole file; the broken SubIFD is skipped and a broken chain IFD ends the chain, matching dcraw (parse_tiff breaks the chain on a bad IFD, dcraw_mod.cpp:6325-6327; tag 330 handling skips a bad SubIFD, dcraw_mod.cpp:5984-5987). IFD0 itself still rejects when unreadable, and the 4096-node cap still fails closed
- RAW loading: an IFD with zero, unpaired or over-limit dimensions no longer rejects the whole file when it is recognisably a preview/thumbnail (NewSubfileType bit 0, or JPEG compression 6/7); it is skipped instead. Without that evidence the rejection stands, and if every dimension-declaring IFD is skipped the file is still rejected. Known accepted residual: a JPEG-compressed main-image IFD with broken dimensions is skipped too, so the gate then validates the thumbnail while the actually-decoded image's broken dimensions go unchecked
- RAW loading: the TIFF gate's "every dimension-declaring IFD was skipped" check now counts an IFD that declares only its height as well as one that declares its width (previously only width counted), so a file whose only dimension declaration is a broken height-only thumbnail is still rejected instead of passing the gate
- RAW loading: an IFD that declares a width or height above 65535 is never skipped as a thumbnail, not even when it is JPEG-compressed; the hard dimension limit is always enforced, so a JPEG-compressed main-image IFD with an over-limit dimension cannot let the gate validate the thumbnail while the decoded image's dimensions go unchecked
- Saving as EXR no longer brightens the image on reload: the writer stored 8-bit sRGB values directly as linear light, while the EXR reader applies gamma 2.2 on decode (mid-grey 128 reopened as ~186). The writer now linearises with the shared Helpers::LinearFromSRGB (gamma 2.2), the same conversion the HDR writer already applied, so save -> reload round-trips pixel-identically
- Saving a JPEG whose EXIF APP1 is malformed (length 6-7, or "Exif" not followed by \0\0) no longer writes two APP1 Exif segments: the segment walker kept the malformed block as an ordinary segment while the EXIF branch also rewrote it, and a reader takes the first (stale) one, losing the orientation reset to 1. The walker's Exif check now matches FindEXIFBlock (length >= 6, first 4 bytes "Exif"), so the malformed block is excluded and rewritten exactly once
- Shutdown: a message posted by a load thread after it signalled completion can no longer reach the window once the image provider has been deleted (the handler and the file-changed handler check for the shutdown state, and the borrowed current-image pointer is cleared)
- The parameter DB is now created on the UI thread before any worker starts, so two load threads can no longer construct it twice, leak one instance or open ParamDB.db concurrently
- Directory watcher: a worker that does not stop within its wait window is no longer followed by deleting the lock and events it still uses; the watcher object is leaked instead, like the image load threads
- TGA viewing: the RLE pixel counter is size_t now, so an image above 2 GB cannot overflow a signed int and write before the buffer
- Colour correction: a degenerate histogram (mean white equal to mean black) no longer divides by zero and feeds NaN into the LUT; the brightness ramp falls back to identity
- JPEG chroma subsampling: an unknown value reported by the decoder is normalized to 4:4:4 instead of indexing the MCU tables out of bounds (affected PSD thumbnails, RAW previews and the lossless-transform eligibility check)
- Saving QOI: the stride and buffer size are size_t now, so an image above 2 GB cannot overflow the copy loop and read out of bounds
- WebP and WIC loading: an unhandled exception is now flagged like every other format, so the file is not memoized as permanently bad
- AVIF loading: when the AVIF decoder throws but the HEIF fallback reads the file, the exception flag is cleared instead of reporting a good image as a crashed load
- APNG viewing: when a frame fails, the EXIF pointer into the destroyed libpng info struct is no longer copied (use-after-free read)
- File type registration: the DACL rebuild compared the wrong expression and dropped every existing ACE, so registering a type replaced the key's permissions with a single allow entry
- File list: CreateFile failures were tested against NULL instead of INVALID_HANDLE_VALUE, so an unreadable or missing file was reported as readable
- Slide show lists: the encoding probe buffer is NUL-terminated before strstr/strchr, and a UTF-8 XML list without a '<' in the probe no longer computes a position from a NULL pointer
- Slide show lists: ANSI lines now use the converted wide-character length, so multi-byte file names no longer drag uninitialised characters behind them
- File type registration dialog: the 49-character JPEG row is no longer truncated and up to 16 extensions per row are registered
- Clipboard: DIBs compressed with BI_RLE8/4, BI_JPEG/BI_PNG or BI_ALPHABITFIELDS are rejected before GDI+ parses them, since no pixel extent can be validated for those layouts
- EXIF: a strip-based (uncompressed) thumbnail is dropped when saving instead of keeping the pre-edit picture in the file
- Batch rename/copy: forward-slash absolute paths are recognised as paths, and a rollback removes the whole directory chain the run created (deepest first) instead of only the innermost one
- Lossless crop: the command itself now rejects non-JPEG and destructively edited images, not only the menu entry
- No black bar when a user command reloads everything: the ClearAllRequests wait is now inside the "waiting for image" guard, so its paint no longer fills the client area
- The window position is saved when the viewer is closed with ESC or the Exit command, not only via the title-bar close button
- Button drawing no longer leaks one GDI bitmap per dimmed paint (the previous bitmap is selected back before the new one is destroyed)
- Single instance: a running viewer with no image open (title exactly "JPEGView") is found again, so the second start forwards its file instead of opening another window
- INI parsing: "nan"/"inf" in UnsharpMaskParameters, ColorCorrection and LandscapeModeParameters are rejected instead of reaching the image filters
- CI: the EOL guard now fails on a project text file whose extension has no rule in .gitattributes (the old check could never fire because the catch-all makes such files report "unset"), and it knows .json/.svg/.bash/.km/.default
- The shipped KeyMap.txt.default and symbols.km are now covered by the text policy (CRLF on disk, LF in the index), like the other delivered configuration files
- README: the image size section describes the current default (no pixel cap, byte and dimension caps still apply) instead of the removed 256 MP default
- Zoom navigator, EXIF panel and help window: a window DC obtained with GetDC was wrapped in a managing CDC whose destructor calls DeleteDC, so every repaint leaked one device context (the navigator leaked one per mouse move)
- Navigation panel animation: the device context was handed to ReleaseDC and then deleted a second time by the CDC destructor on the same handle
- Shutdown: the second image-processing parameter set is freed instead of leaking once per session
- Shutdown: the retained printer dialog and print parameters are freed by a new CPrintImage destructor
- Help window: the info column colour was read from a shadowing file-scope constant, so the on/off entries never used the intended colour; a key that does not fit the text buffer is skipped instead of crashing the layout
- Case-insensitive substring search: an allocation failure no longer passes NULL to _tcslwr
- Parameter DB error dialog: a failed FormatMessage no longer appends a NULL string to the message
- Window placement: a failing GetMonitorInfo no longer returns an uninitialised monitor rectangle
- BMP loading: a height of INT_MIN is rejected instead of reaching abs()/negation (undefined behaviour)
- CMYK ICC profile: a truncated module path is detected by the returned length instead of a stale last-error value
- File type registration: an empty extension segment no longer registers an empty name or reads past the list buffer
- CI: the WICLoader import-library cleanup step no longer fails when a file is already absent, and the WICLoader project uses the same /EHa exception model as the main project
- JPEG 2000: CMYK files (colr enumCS 12) are now decoded and converted through the bundled cmyk.icm profile (naive ink formula only when the profile is unavailable) instead of being rejected and shown as an empty state
Engineering:
- CI: actions/upload-artifact upgraded from v4 to v7 (Node 20 deprecation warning); Debug|Win32 build now verified with a /SAFESEH check
- CMYK plane polarity now lives in one header (YmckDecode.h) with endpoint assertions and a CI gate, so the PSD/JP2/JPEG ink conversion cannot be inverted or inverted twice again; tests/ymck_decode_test.cpp runs on any platform, and JPEGVIEW_DISABLE_CMYK_ICC=1 makes the no-profile fallback reachable for testing

[1.3.46-20261107] 2026-11-07
New features:
- Add JPEG 2000 (JP2/J2K/J2C) viewing and saving (OpenJPEG 2.5.4)

- Add PGM/PNM, AVIFS, ICB/VDA/VST, HDR (RGBE) and PBM viewing; PAM (P7) Netpbm viewing; true Windows cursor (.cur) support
- Add INI settings: OcrShortcut (default Ctrl+Q), OcrLanguages (default zh-CN,zh-TW,en-US), FileEndingsExtra (extra browsable extensions, MAX_ENDINGS raised to 128)
- Version stamp from git tag: tagged builds show the tag, development builds show the last release plus a dev marker
- Add JXL encode null-check and ConvertToJXL JPEG-source guard (crash fixes)
- Add CMYK ICC profile delayed-open + path buffer fix (MAX_PATH+16) with bundled cmyk.icm
- Add PSD CMYK fixed 4-channel YMCK (avoid alpha-channel bugs)
- Add TIFF OOM fallback to WIC reader (reset OutOfMemory before retry)
- Add JXL single-pass BGR->RGB copy + 1 MB output pre-allocation (encode speed)
Bugs fixed:
- Animated image switching no longer corrupts the heap (per-thread animation caches)
- JPEG 2000 save now works (the image rectangle is set explicitly; previously every JP2/J2K/J2C save failed)
- Switching images no longer risks drawing a freed image while the load wait pumps paint messages
- Uncompressed TGA at 8bpp is rejected instead of returning an uninitialized buffer
- WebP files with an ICC profile no longer leak the color transform and EXIF chunk on decode failure
- AVIF files rejected by the pixel cap no longer fall back to a second full HEIF parse
- Copying a very large image no longer silently empties the clipboard when the allocation fails (and now reports the failure)
- Pasting an image with a huge palette size in the clipboard header no longer reads out of bounds
- SVG files with a very long root tag are no longer rejected as size-less
- The per-thread whole-file read buffer is released after a request once past 64 MB (lower memory after opening a large file)
- Oversized images now report the size limit instead of "Not enough memory", and raising MaxImagePixelsMP now applies to all decoders
- SVG text no longer disappears after browsing away and back
- Startup out-of-memory now shows a message instead of exiting silently
- Numerous robustness fixes from code review (clipboard, KeyMap, file watcher, thumbnail and paint paths)
- JXL save/convert no longer dereferences NULL output
- TIFF read failure no longer sticks OutOfMemory flag
- CMYK profile no longer opened on invalid path
Changed behavior:
- MaxImagePixelsMP default raised from 100 to 256 megapixels: 100 rejected real photos (102 MP medium format, 108 MP phones, 200 MP phones); 256 covers every single-shot camera (largest is a 200 MP phone sensor at 201 MP) with headroom, and still blocks absurd dimensions. Existing INI files that already set MaxImagePixelsMP keep their value; the new default applies to fresh installs and INI files without the key.

  PR #143, thanks qbnu (GH https://github.com/qbnu)

  PR #150, thanks qbnu (GH https://github.com/qbnu)

  Modified backport feature from fork by David Neon (GH https://github.com/sdneon)

- New INI file setting: "FlashWindowAlert"
  When WrapAroundFolder=false, briefly flash window when attempting to navigate beyond the beginning or end of the file list.
  (Default to enabled, since it's visual UI feedback)

  When WrapAroundFolder=false, play the system beep sound when attempting to navigate beyond the beginning or end of the file list.
  (Default to disabled, since audio feedback can be an annoyance)

  Dragging the handles in Top-Left and Bottom-Right will change to portrait or landscape orientation if dragging in the direction to "pull" the crop into the other orientation.  (Top-Left pull by w, Bottom-Right pull by h)
  (Effectively doubles the aspect ratios natively supported into portrait orientations)

- Fixed: Transparency color for some image types was reversed BGR
  PR #145, thanks qbnu (GH https://github.com/qbnu)
- Fixed: TGA used background color for transparency instead of transparency color
- When viewing the last frame of a multi-frame image, at the end of the file list, with option WrapAroundFolder=false, attempting to navigate to the next frame will no longer loop back to frame 0

- Restores ICC Profile support for PNGs by using GDI+ when ForceGDIPlus=true or UseEmbeddedColorProfiles=true options set.  NOTE: Disables animated PNG support.
  PR #149, thanks qbnu (GH https://github.com/qbnu)

  Previous behavior: Always zoomed to center when a new image was loaded

[1.0.27] 2013-01-20
Replaced Intel JPEG library by Turbo JPEG (tjpeg, http://sourceforge.net/projects/libjpeg-turbo/)
This replacement has many reasons:
- The Intel library license was not an open source type license
- Newer versions of the Intel library are not free of charge. The old versions are not supported by Intel anymore.
- Some JPEG files could not be read by the Intel library. tjpeg can read these files.
- There is no free 64 bit version of the Intel library.
  (This is important for the future when there may be a 64 bit version of JPEGView)
The tjpeg library is open source and (at least on modern CPUs) performs comparable to the Intel library. It is used by many other
viewers and several Linux distributions.
Note that tjpeg including lossless JPEG transformations has been statically linked to JPEGView. Therefore the application has grown
by 300 KB. However the total size of the package is lower than before because IJL15.dll and jpegtran.exe are no longer needed.

Bugs fixed:
- When a folder is called 'pictures.jpg' for example, JPEGView no longer tries to process this folder as image
- Exposure time display: When nominator and denominator are both big numbers, a fractional value is shown instead of bigNum/bigDenum
- Reading slideshow list files (txt) encoded with UTF-8 and UTF-16 (little endian only) correctly
- Reading slideshow list files (txt) using uppercase file endings for image files correctly
New features:
- Lossless JPEG transformations integrated into JPEGView. The jpegtran.exe application is no longer part of the distribution of JPEGView.
- Basque translation, thanks to Xabier Aramendi
- Chinese translation, thanks to Yia Guo
- Keymap.txt now also supports to remap mouse buttons to commands.
- New INI file setting: 'TrimWithoutPromptLosslessJPEG'. Set to true to trim image before lossless JPEG transformations if needed without
                        prompting the user for each image.
- New INI file setting: DefaultWindowRect=sticky to save and restore the window size and position in window mode
- New INI file setting: 'SingleInstance'. Set to true to open all images in one single instance (window) of JPEGView.
- New INI file setting: 'ShowBottomPanel'. Set to false to disable showing the bottom panel when hovering with the mouse on bottom part
  of window/screen.
  Default is true (as before, was not configurable).
- New INI file setting: 'MaxSlideShowFileListSizeKB'. Sets maximum size of slide show text files in KB.
- New INI file setting: 'ForceGDIPlus'. If true, use GDI+ for reading JPEGS. Note that using GDI+ is much slower than the tjpeg library!
- New command line parameters:
  /slideshow xx    Starts JPEGView in slideshow mode, xx denotes the switching time in seconds. Only use when providing a file name,
                   folder name or file list on the command line as first parameter.
                   Example: jpegview.exe "filelist.txt" /slideshow 2
  /fullscreen      Starts JPEGView in full screen mode, ignoring the INI file setting that is currently active
  /order x         Forces file ordering mode 'x', ignoring the INI file setting that is currently active
                   'x' can be M, C, N or Z, for the file ordering modes 'M:modification date', 'C:creation date', 'N:file name', 'Z:random'
                   Example: jpegview.exe c:\pictures /slideshow 2 /order z
